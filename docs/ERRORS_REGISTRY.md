# Реестр ошибок и опыта

Канон для клиента Windows. Краткие записи по симптому, причине и тому, что делать. Дубликаты не плодить: обновлять существующую строку.

Нумерация **ERR-NNN** сквозная. Корневой файл не заводить.

## ERR-001 - Windows: рекламных слотов нет, вотчер ни при чём

| Поле | Значение |
|------|----------|
| **Дата** | 2026-11-16 |
| **Контекст** | Корпоративный ПК, официальный `Spotify.exe` **1.3.9.2055** с `--log-file` и `--debug-level=8`, рядом работает `watch.py`. Вход на этот ПК сделан QR-кодом с телефона; телефон в тот момент был в сети домашнего роутера **3811**. Это фиксирует, откуда взялась учётная запись, и само по себе не доказывает подмену рекламного CDN |
| **Симптом** | За сессию рекламы не было, запросов к рекламе будто нет |
| **Состояние** | Журнал около 10 МБ: сотни строк `spotify:track:` (prefetch) и ноль `spotify:ad:`, `ad_break`, `audio_ad`, `advertisement`. Строк `track_uri` нет, вотчер читает медиасессию; статус только `spotify:track:smtc:1`. WinHTTP без прокси, в `hosts` нет Spotify. DNS корпоративные, но `audio-fa.scdn.co`, `heads-fa.scdn.co`, `adeventtracker.spotify.com` и `spclient.wg.spotify.com` резолвятся в публичные адреса. В локальных `prefs` поля тарифа нет |
| **Причина** | Так ведёт себя учётная запись, которой сервер не выдаёт рекламу. В локальных prefs поля тарифа нет, поэтому тип подписки по файлу не подтверждён. Если бы бесплатный аккаунт упирался в блокировку рекламного CDN, в журнале всё равно остались бы попытки рекламного слота. Их нет. Резолв рекламных имён с ПК показывает, что роутер на этом пути рекламный CDN не подменяет |
| **Что делать** | Не чинить вотчер и не искать блок CDN, пока в журнале нет ни одной попытки рекламного слота. Сначала проверить, получает ли рекламу учётная запись на телефоне, с которого был QR |

## Как добавлять записи

1. Идентификатор **ERR-NNN** - следующий свободный после максимального номера в этом файле. Дыры и уже занятые номера не заполнять
2. Одна таблица здесь: дата, контекст, симптом, причина, что делать. Состояние добавлять, когда без него запись не воспроизвести
3. Корневой `ERRORS_REGISTRY.md` не заводить
4. Имя входа RDP, идентификатор Spotify из `prefs` и внутренние адреса корпоративных резолверов в запись не копировать
